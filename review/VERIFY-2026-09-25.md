# Verification of the 2026-09-18 work, and what it missed

**Date:** 2026-09-25
**Method:** read the shipped code in full; reproduce every suspected defect
against the real CLI or a real container before changing anything; have a second
reviewer, told to disprove each finding, reproduce them independently. None was
refuted. Each fix is then held by a test and, for `scripts/hiddenforge`, by a
curated mutation that the test kills.

## What was confirmed working

Host suite, ruff, mypy (31 files) and the manifest check were green on the
2026-09-18 tree. In a container built from it: supervisor keeps `0xc2` with the
Docker capability set and `0xc0` with the Podman set (10 of 10 starts); Tor runs
as uid 100 with an empty effective set under a seccomp filter. The restore
symlink/traversal, keyless-archive, control-character and `--delete-plaintext`
fixes behaved as described.

## Honest limits of the fixes

- **The pin protects the signature directory, not the CLI.** If both come from
  one compromised clone, the pin is compromised with them. The fingerprints are
  in `signatures/README.md` and should also be published somewhere independent.
- **Finding 4 is fail-closed either way.** It never ran Tor as root; it refused
  to start. The cost was availability, hidden by `logging: driver: none`.
- **One run of the curated check before this fix was not evidence** for the
  mutation whose target was mis-split; the others ran real tests.

## Later the same day: the pre-publication pass

Five more adversarial review rounds, each run against the previous round's fixes
and against code not yet examined, each finding reproduced before it was fixed.
The CHANGELOG's "pre-publication pass" section lists them. The ones that matter
most for someone relying on this:

- The supervisor's address publisher could be turned against the key: a
  hardlink at its predictable temp name had the secret key overwritten and made
  world-readable, as root; a FIFO or a link to `/dev/zero` in the key volume hung
  or killed PID 1.
- A corrupted pip hash did not fail the image build (a shell `|| true` swallowed
  it); proven fixed by building a copy with one corrupted hash.
- `restore`/`decrypt-key` accepted a truncated key as an identity.
- `doctor` failed the recommended Docker deployment from the host, and could pass
  a service it never checked.

The fifth round found only a documentation path error, fixed in `595ca81`.

Final state (image-affecting commit `390e2da`): the curated mutation check kills
42/42 (every kill is a failing test, never a pytest error); every CI job passes
locally except the security job's artifact upload, which needs the Forgejo server;
amd64 and arm64 both reproduce bit for bit; the committed compose boots and
publishes; the live E2E passes. `docs/PRODUCTION-READINESS.md` has the numbers.
